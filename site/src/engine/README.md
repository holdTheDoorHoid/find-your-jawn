# Matching engine

Pure TypeScript. No DOM, no network, no storage. The quiz island hands it the groups, the
vocabulary and the visitor's answers, and gets back about eight ranked results with reasons.
Spec: `docs/DESIGN.md` sections 3, 4 and 12.

```ts
import { buildCatalog, computeResults } from '../engine';

const cat = buildCatalog(quizConfig);                 // vocabulary, once
const out = computeResults(groups, cat, answers);     // groups come from normalizeGroupsFile
out.results   // Result[]: group, kind (close, stretch, wildcard), why, stretchLine, notes, firstStep
out.diagnosis // which locked answers are ruling groups out, for the honest empty state
```

## Pieces

| File | What it does |
|---|---|
| `types.ts` | `Answers` (what the quiz saves), `CatalogData`, `Result`, the score `Parts` |
| `catalog.ts`, `centroids.ts` | The vocabulary with lookups, and the middle of every neighborhood and ZIP (generated by `scripts/make-centroids.mjs`) |
| `profile.ts` | Turns answers into numbers: interest weights, roles and formats, motives, future selves, strangers, home, and what the taste test and "Not for me" taps taught |
| `prepare.ts` | One pass per group: families, parent organization, places with coordinates, ways in |
| `filters.ts` | Hard filters. Every locked answer is pass, fail or unknown. Also `diagnose` and `loosen` |
| `score.ts` | The eight parts and `WEIGHTS` (the one place the weights live), `rankTier` |
| `crowd.ts` | Who is in the room and whether that is who the person wants to meet |
| `stretch.ts` | The four axes (`axesOf`), stretch candidates, the wildcard |
| `select.ts` | The adventure dial, the variety rule, show me more, replacing a card |
| `explain.ts` | Why a group fits, the stretch sentence, notes, the first step |
| `taste.ts` | Which real groups to show in the taste test, and which follow up questions to ask |
| `checkin.ts` | "Did you go?": the next rung, and a similar group that removes what got in the way |
| `travel.ts` | Travel time estimates. **The one place that knows how people get around** |
| `answers.ts` | Reads answers back from browser storage, throwing away anything invalid |
| `test-groups.ts`, `testing.ts` | About sixty made up groups with real gaps, and the ten fixture people. Tests only |

## Rules worth knowing

- **Gaps are not no.** A fact the group's page does not give scores neutral (about 0.5) on that part,
  and the confidence part reflects how thin the record is. A question the person skipped scores 0.5 for
  every group, so it cannot split them. Nothing throws on a thin record.
- **Locked answers on unknown facts.** The group passes, but is shown after every group we could confirm
  (`rankTier`: 0 confirmed, 1 or 2 unconfirmed answers, 3 no place found when distance is locked), and the
  card says what is not listed ("Cost not listed.", "Location not listed.").
- **Hard rules no answer loosens:** closed or quiet groups, partisan groups, members only and invitation
  only groups, another school's students only group, age, support groups unless asked for, faith groups for
  someone who excluded them or only wants their own tradition.
- **Court ordered service** shows only groups with a yes. An unknown is not good enough.
- **Stretches change exactly one thing** (`axesOf`: topic, way in, crowd, depth). They never break a
  practical limit (checked with every practical answer treated as locked), never include support groups,
  and include faith groups only for people who chose to include faith. A stretch needs a known place.
- **The wildcard** is very welcoming (a rating of 4 or 5), free or low cost, drop in or one time, practical
  for the person, not an interest they asked for, and tied to something they said. It needs a published
  rating, so with data that has no ratings there is no wildcard. That is on purpose.
- **Variety:** no more than two results share a primary interest family or a parent organization. The
  parent organization is worked out from the group's name (`orgKey` in `prepare.ts`); use a `parent_org`
  field when the data has one.

## Seams for later

- **The simulation that tunes the weights (DESIGN section 12) is not built.** Everything it needs is
  exported: `WEIGHTS`, `NEWCOMER_WEIGHT_HARD` and `PATH_BOOST` in `score.ts`, `INTEREST`, `LIKED` and
  `MOTIVE_WEIGHT` in `profile.ts`, `DIAL` and `VARIETY_CAP` in `select.ts`, `FOLLOW_MIN_CHANGE` and
  `TASTE_COUNT` in `taste.ts`. `computeResults(groups, cat, answers, { now })` is deterministic, so a
  script can generate synthetic `Answers`, call it thousands of times and measure how often groups that
  truly fit land in the top eight. Record every weight change in the DESIGN section 3 table.
- **Real transit times:** implement `TravelModel` (`travel.ts`) and pass it as `travel` in the options.
  Nothing else changes.
- **Pictures for scenes:** the island shows each scene's emoji until the vocabulary has a `picture`.
