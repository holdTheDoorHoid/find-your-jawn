# Data model (binding contract)

Everything the pipeline, the research agents and the site exchange is defined here. Change this file
in the same commit as any code that changes a format, and say so in your report.

There are three layers:

1. **Sources** (`registry/sources.yaml`): where information comes from and on what terms.
2. **Leads** (`data/leads/<source>.jsonl`): raw candidate records, one per thing a source lists.
   Internal only. Many leads can describe the same real group.
3. **Groups** (`data/groups/<first character>/<slug>.yaml`): one file per real group, written in our
   own words, merged from leads and research. This is what the site publishes.

## 1. Sources registry

`registry/sources.yaml` is a list. Each entry:

```yaml
- id: city_rco                 # short snake_case id, used as the leads file name
  name: Registered Community Organizations (City of Philadelphia)
  owner: City of Philadelphia, Department of Planning and Development
  url: https://services.arcgis.com/fLeGjb7u4uXqeF9q/ArcGIS/rest/services/Zoning_RCO/FeatureServer/0
  access: arcgis_rest          # arcgis_rest | csv | json_api | html | pdf | agent_read | manual
  terms: City of Philadelphia License (free reuse, as is)
  attribution: "Data: City of Philadelphia"
  lead_only: false             # true = terms forbid republishing; use only to find groups
  refresh: monthly             # weekly | monthly | yearly | after_event | manual
  harvester: pipeline/fyj/harvest/arcgis.py
  notes: Primary contact is often a named person with a personal email and phone.
```

## 2. Leads

One JSON object per line in `data/leads/<source id>.jsonl`, sorted by `lead_id` so diffs stay small.
Unknown values are `null` or empty lists, never invented. Fields:

| Field | Type | Meaning |
|---|---|---|
| `lead_id` | string | `<source id>:<native id>`; stable across harvests |
| `source` | string | source id from the registry |
| `source_url` | string | the page or API query this record came from |
| `native_id` | string | the source's own id (EIN, object id, club code, page slug) |
| `name` | string | name as the source gives it |
| `aka` | list of strings | other names (dba names, short names, public names) |
| `kind_hint` | string or null | `nonprofit`, `civic`, `student_org`, `club`, `friends_group`, `garden`, `congregation`, `team`, `parade_unit`, `grantee`, `library_program`, `facility`, `other` |
| `description` | string or null | source text, internal only, never published |
| `website` | string or null | |
| `email` | string or null | as published |
| `phone` | string or null | as published |
| `social` | list of strings | URLs |
| `contact_name` | string or null | as published |
| `address` | string or null | street address |
| `city` | string or null | |
| `zip` | string or null | five digits |
| `lat`, `lng` | number or null | WGS84 |
| `meeting_place` | string or null | |
| `schedule_text` | string or null | as published, for example "first Thursday, 7 pm" |
| `school` | string or null | for student groups: `penn`, `drexel`, `ccp`, `temple`, ... |
| `open_to_public_hint` | true, false or null | what the source implies about non members joining |
| `ein` | string or null | nine digits, no hyphen |
| `ntee` | string or null | IRS NTEE code |
| `irs_subsection` | string or null | for example `03` for 501(c)(3), `19` for veterans posts |
| `irs_status` | string or null | IRS status code |
| `tags_hint` | list of strings | the source's own categories or tags |
| `seen_at` | list of objects | `{source_url, date, note}` for event and parade sightings (year marched, cleanup hosted) |
| `extra` | object | anything else the source provides that might help later |
| `harvested_at` | string | ISO date of the harvest |

Leads files are regenerated by harvesters and committed. Raw downloads stay in `$FYJ_CACHE`.

## 3. Groups

One YAML file per real group at `data/groups/<first character of slug>/<slug>.yaml`. The slug is
lowercase ASCII words joined by hyphens, for example `philadelphia-grotto`. Fields marked (req) must
be present before a group is published.

```yaml
id: philadelphia-grotto                 # (req) equals the slug
name: Philadelphia Grotto               # (req)
aka: [Philly Grotto]
leads: [nss_grottos:philadelphia-grotto]  # lead ids merged into this group
ein: null

# What it is, in our own words
summary: A caving club that runs trips to caves in Pennsylvania and nearby states and teaches beginners how to cave safely.   # (req) one or two plain sentences, our words
what_you_do: Join monthly meetings and weekend caving trips; beginners go with experienced members.
kind: club                              # (req) nonprofit | civic | club | team | student_org | congregation | friends_group | garden | program | network | support_group
categories: [outdoors-adventure]        # (req) interest families from data/vocab/interests.yaml
interests: [caving, hiking, geology]    # (req) interest tags from the same vocabulary
motives: [social, understanding, enhancement]   # see vocabulary: values, understanding, social, career, protective, enhancement
formats: [side_by_side, learn_skill]    # see vocabulary in data/vocab/formats.yaml
roles: [hands_on, figure_out]           # what you do there: hands_on | figure_out | create | help_teach | lead | organize
crowd: [all_adults]                     # who is there, see data/vocab/audiences.yaml
bridging: false                         # true when the group mixes ages, neighborhoods or backgrounds on purpose

# Who can join
audience:
  open_to: public                       # (req) public | students | members | parents | residents | invite
  school: null                          # for student groups
  min_age: 18
  max_age: null
  community: []                         # optional affinity, for example [lgbtq], [veterans], [irish_heritage]
  faith: null                           # null, or a tradition such as catholic, muslim, interfaith
  partisan: false                       # must be false to publish
  support_group: false                  # true = shown only when someone asks for support groups

# When and where
schedule:
  text: First Thursday of each month, evening meeting; trips on weekends   # our words
  days: [thu, sat, sun]
  times: [evening, daytime]
  recurring: true
  season: year_round                    # year_round | spring | summer | fall | winter | event_only
locations:
  - label: Monthly meeting
    address: null
    neighborhood: null                  # from data/vocab/neighborhoods.yaml
    zip: null
    lat: null
    lng: null
    in_city: false                      # false for regional groups that serve the city
    transit: null                       # nearest SEPTA stop or line, if known
online_ok: false

# Practical facts
cost:
  level: low                            # free | low | paid | unknown
  text: Annual dues; trips cost gas and gear rental
commitment: monthly                     # one_off | drop_in | monthly | weekly | ongoing_role | seasonal
group_size: small                       # small (under 15) | medium (15 to 60) | large | varies
access:
  wheelchair: unknown                   # yes | partial | no | unknown
  languages: [en]
  notes: null
requirements:
  act153_clearances: false              # works with children, Pennsylvania clearances required
  background_check: false
  court_ordered_ok: unknown             # yes | no | unknown; yes only with a source that says so
  service_hours_letter: unknown         # yes | no | unknown; will sign off teen or court hours
  kids_ok: false                        # children can take part with a parent
  gear: Helmet and lights; the club lends gear to beginners

# The first visit (deep research tier)
first_step:
  how: Come to a monthly meeting before signing up for a trip   # one concrete action
  drop_in: true                          # can you just show up
  sign_up_needed: false
  newcomer_friendliness: 4               # 1 to 5, see basis
  basis: Club site invites beginners and describes a beginner trip program
  what_to_expect: null                   # our words, a few sentences
  first_visit_tips: []                   # short bullets

# Contacts, copied as published (owner decision 2026-10-04)
contacts:
  website: https://phillygrotto.org
  email: null
  phone: null
  contact_name: null
  social: []
  calendar_feed: null                    # iCal or RSS the group publishes itself

# Is it alive
status: active                           # active | probably_active | dormant | defunct | unknown
last_sign_of_life: 2026-09               # year and month of the newest dated evidence
sign_of_life_url: https://phillygrotto.org

# Provenance
sources:
  - url: https://caves.org/grotto/philadelphia-grotto/
    seen: 2026-10-04
    fields: [name, contacts.website]
research_tier: 1                         # 0 harvested | 1 basic | 2 deep | 3 confirmed by the group
confidence: medium                       # high | medium | low
last_checked: 2026-10-04
hidden: false
hidden_reason: null                      # out_of_scope | partisan | defunct | duplicate | private | removal_request
```

### Status rules

- `active`: dated evidence (event, post, meeting notice, filing, news) within the last 12 months.
- `probably_active`: newest evidence 12 to 24 months old, or undated evidence on a working site.
- `dormant`: newest evidence older than 24 months.
- `defunct`: dissolved, merged, or announced closed. IRS revocation alone is NOT proof of death:
  small groups often stop filing and keep meeting.
- `unknown`: no evidence either way yet.

Every published listing shows "last seen active" from `last_sign_of_life`.

### Research tiers

- Tier 0: created from leads by script; only name, kind, address and contacts. Hidden from the quiz
  until it reaches tier 1, visible in browse with an "unverified" label.
- Tier 1: basic pass (alive, joinable, summary, tags, cost, schedule if easy).
- Tier 2: deep pass (first visit, newcomer friendliness with basis, requirements, access).
- Tier 3: the group itself confirmed the listing through a GitHub issue.

## 4. Vocabularies

Controlled lists live in `data/vocab/`:

- `interests.yaml`: interest families and tags, plus an adjacency graph used for stretch picks. Each
  edge has a type: `same_skill`, `same_crowd`, `same_place`, `same_cause`, `same_topic`.
- `ways_in.yaml`: for each interest, the five ways in (do it, learn it, teach it, serve it, lead it).
- `motives.yaml`: the six Volunteer Functions Inventory motives with plain language labels.
- `formats.yaml`: how people spend time together (side by side, conversation, team play, perform or
  make together, behind the scenes, lead and organize, learn a skill, one off event).
- `audiences.yaml`: crowd and community labels.
- `roles.yaml`: the six roles (what you do there), a compact take on the Holland interest types.
- `scenes.yaml`: the quiz's Saturday morning scenes and "lost track of time" moments, each mapped to
  interests, roles and formats, with picture credits.
- `future_selves.yaml`: the "a year from now" statements, each mapped to interests, roles and ways in
  that move a person toward it.
- `neighborhoods.yaml`: neighborhood names with planning district, from the City's neighborhood
  boundaries.

## 5. Site data (built, not committed)

The pipeline's build step writes `site/public/data/`:

- `groups.json`: compact index of every published group (the quiz and browse load this).
- `groups/<slug>.json`: full record per group for its page.
- `vocab.json`: merged vocabularies.
- `manifest.json`: build date, counts by status, tier, category and planning district, and the
  coverage estimates from `research/coverage/`.
